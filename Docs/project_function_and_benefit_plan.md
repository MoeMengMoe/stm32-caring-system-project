# 项目功能清单与预期收益方案

更新时间：2026-06-07

## 1. 项目定位

本项目当前建议定位为：

**基于 STM32U5 的隐私优先型边缘自治独居看护系统**

核心叙事不是“跌倒检测器”，而是：

- 在无普通摄像头、弱网络依赖的家庭环境中；
- 通过非成像多模态感知、本地状态机、可解释风险逻辑和本地交互闭环；
- 实现对独居老人生活状态与风险事件的持续感知、判断、确认、告警和日志留存；
- 并为后续低功耗、电池供电和最小运行版本演进预留架构基础。

## 2. 当前已具备功能清单

### 2.1 基础平台与工程能力

- STM32U5 CubeMX + CMake + CLion 工程已跑通。
- 基础串口日志、LED 心跳、主循环运行框架已具备。
- 项目文档、引脚说明、验收记录已有基础沉淀。

### 2.2 环境感知能力

- `BME280` 温度采集。
- `BME280` 湿度采集。
- `BME280` 气压采集。
- `MQ2 / MQ 模块 AO` 模拟量采集与数值回传。

### 2.3 人体相关感知能力

- `24GHz 雷达` 基础接入已完成。
- 雷达 UART 数据解析能力已具备。
- 已有或已验证过的雷达特征包括：
  - `presence`
  - `distance`
  - `zone`
  - `gate energy`
  - `motion score`
  - `occupied/still seconds`

说明：

- `PIR` 模块计划移出主方案，不再作为后续核心功能路径。

### 2.4 本地显示与交互能力

- TFT 屏幕已可正常显示。
- 本地状态页已有实现基础。

### 2.5 联网与远程展示能力

- STM32 状态帧发送链路已具备。
- ESP8266 UART CSV 解析能力已具备。
- ESP8266 MQTT JSON 转换与上报已具备。
- `Home Assistant` 已能接收并展示温湿度、MQ2 等数据。
- 当前已实现真实环境数据回传到 HA 的基础链路。

## 3. 当前尚未完成但必须补齐的核心功能

这些功能不是“锦上添花”，而是当前项目从“采集展示 demo”升级为“系统作品”的关键。

### 3.1 风险规则与状态机

- 正式风险状态机。
- 状态优先级定义。
- 状态进入条件与退出条件。
- 中风险、高风险、无响应、故障态的处理逻辑。

### 3.2 雷达验证与标定

- 验证 `24GHz 雷达` 在不同场景下的稳定性。
- 明确哪些雷达特征可以进入规则，哪些只适合调试。
- 建立基础场景日志：
  - 无人
  - 活动
  - 坐卧久静
  - 地面久静
  - 离房

### 3.3 本地自治闭环

- 蜂鸣器告警。
- 按钮确认。
- 本地确认超时升级。
- 本地状态与风险提示闭环。

### 3.4 可解释输出

- 风险分 `risk_score`。
- 当前状态 `state`。
- 最近事件 `event`。
- 告警证据链 `evidence`。

### 3.5 日志缓存机制

- 最近事件环形缓存。
- 关键状态切换记录。
- 关键风险触发记录。
- 为后续离线补传、追责分析和实验复盘保留基础。

### 3.6 后续预研方向

- 低功耗运行策略。
- 18650 电池断电支撑。
- 最小运行版本定义。
- 企业开发模式下的模块化和功耗分层设计。

## 4. 计划保留的功能方案

### 4.1 主控与边缘自治主线

- STM32U5 作为本地主控。
- 本地完成状态判断、风险分级和响应控制。

预期收益：

- 强化“边缘自治”叙事。
- 降低对网络和云端依赖。
- 契合 ST 半导体赛道对低功耗和工程化能力的偏好。
- 更符合嵌入式系统设计竞赛的评审偏好。

### 4.2 24GHz 雷达主人体感知

- 以 `24GHz 雷达` 作为当前主人体感知模态。
- 重点利用 `presence / zone / motion score / still seconds`。

预期收益：

- 作为非视觉、隐私友好的主感知源。
- 比 PIR 更适合空间状态理解。
- 能支撑“活动/久静/离房”等场景判断。

### 4.3 MQ2 环境风险感知

- 保留 `MQ2` 作为燃气/气体异常的环境风险源。

预期收益：

- 能形成“人身风险 + 环境风险”双主线。
- 扩大项目应用边界，不局限于跌倒类话题。

### 4.4 BME280 环境上下文

- 保留温湿度与气压信息。

预期收益：

- 为环境状态提供上下文。
- 可作为长期环境变化、舒适度与异常背景信息。

### 4.5 TFT 本地状态显示

- 保留 TFT 作为本地可视化与交互载体。

预期收益：

- 现场演示效果直观。
- 可显示状态、风险分、网络状态和最近事件。
- 强化“本地自治节点”产品形态。

### 4.6 MQTT + Home Assistant

- 保留 MQTT 上报和 HA 面板。

预期收益：

- 完成“本地自治 + 远程同步”的双层展示。
- 便于答辩展示事件时间线和远程状态。

### 4.7 低功耗演进路线

- 将低功耗纳入系统后续设计目标。
- 预留断电后由 `18650` 电池维持一段时间运行的能力。
- 后续考虑按状态关闭部分外设，形成最小运行版本。

预期收益：

- 更贴合 ST 赛道“低功耗 + 工程化”的方向。
- 让作品更接近真实企业级产品思路。
- 为后续升级为便携式、断电可持续运行节点提供基础。

## 5. 计划删除或降级的功能方案

### 5.1 PIR 模块

- 不再作为主方案核心人体感知模块。

原因：

- 感知范围小。
- 空间约束强。
- 对朝向和位置敏感。
- 相比 `24GHz 雷达` 增益有限。
- 增加系统冲突和调试复杂度。

预期收益：

- 减少无效联调时间。
- 简化事件源。
- 将精力集中在更有价值的感知模态上。

### 5.2 所有视觉模块

- 不再主攻热阵列、成像视觉、空间热图展示等方向。

原因：

- 与“隐私优先”叙事不完全一致。
- 会占用较多硬件接入和算法处理时间。
- 容易把项目带回“视觉检测”路线，削弱系统创新主线。

预期收益：

- 节省开发时间。
- 保持项目技术路线统一。
- 更容易形成“非成像感知”亮点。

## 6. 计划新增的功能方案

### 6.1 风险状态机

建议状态：

- `NORMAL`
- `ACTIVE`
- `RESTING`
- `LONG_STILL`
- `GAS_RISK`
- `NO_RESPONSE`
- `SENSOR_FAULT`

预期收益：

- 把项目从“原始数据展示”提升为“状态理解系统”。
- 每个演示场景都能映射到清晰状态。
- 便于写报告、做答辩和做现场演示。

优先级：

- `最高`

### 6.2 事件层

建议事件方向：

- `PresenceDetected`
- `PresenceLost`
- `ZoneChanged`
- `LongStillness`
- `MotionBurst`
- `GasRising`
- `GasHigh`
- `UserAck`
- `UserNoResponse`
- `SensorFault`
- `NetworkLost`

预期收益：

- 降低规则与单一传感器强耦合。
- 为后续新增传感器保留统一接口。
- 强化架构层面的创新性。

优先级：

- `最高`

### 6.3 可解释风险分与证据链

建议输出：

- `risk_score`
- `confidence`
- `evidence[]`
- `action[]`

预期收益：

- 回答“为什么报警”这一关键评委问题。
- 提高系统可信度。
- 形成区别于普通上传型 IoT 项目的亮点。

优先级：

- `最高`

### 6.4 蜂鸣器 + 确认按钮

建议功能：

- 中风险短响提示。
- 等待用户确认。
- 无响应升级。
- 长按触发主动求助或保留扩展。

预期收益：

- 建立“询问-确认-升级”的自治闭环。
- 从监测系统升级为照护交互系统。

优先级：

- `高`

### 6.5 日志缓存机制

建议功能：

- 最近事件环形缓存。
- 最近状态切换记录。
- 风险触发和用户确认日志。
- 为后续断网缓存、离线补传和实验分析预留接口。

预期收益：

- 强化工程规范性和可追溯性。
- 有助于实验复盘、日志展示和答辩材料整理。
- 为后续更高级的缓存补传和系统审计能力打基础。

优先级：

- `高`

### 6.6 压力垫

建议功能：

- `BedOccupied`
- `BedNotOccupied`

预期收益：

- 显著降低“床上久静”误报。
- 为“休息/异常久静”提供强上下文。
- 是低成本高收益增强模态。

优先级：

- `高`

### 6.7 继电器

建议功能：

- 燃气高风险时联动排风/灯光等模拟干预。

预期收益：

- 把“报警”升级为“主动干预”。
- 更像产品，而非实验板。

优先级：

- `中高`

### 6.8 ESP32-S3 Wi-Fi CSI 感知模块

建议定位：

- 作为替代视觉模块的隐私优先增强模态。
- 不作为第一阶段主判据。
- 作为辅助事件源接入主状态机。

建议输出的辅助事件或特征：

- `CSIMotionDetected`
- `CSILongStillness`
- `CSIPresenceHint`
- `CSIActivityDrop`

预期收益：

- 强化“非成像、隐私优先”的技术路线。
- 为人体活动变化和异常久静提供额外证据。
- 在答辩中形成区别于普通雷达方案的新亮点。

风险提醒：

- 短期内不宜承诺高精度跌倒检测。
- 更适合作为辅助模态，而不是唯一判据。

优先级：

- `中高`

### 6.9 低功耗与电池供电路线

建议方向：

- 分析当前外设功耗组成。
- 规划“全功能运行 / 演示运行 / 最小运行”三档模式。
- 后续支持断电后由 `18650` 电池维持一段时间运行。
- 在最小运行版本中关闭部分高功耗外设，仅保留关键感知、状态机和必要告警。

预期收益：

- 强化 ST 赛道特征，不只是“功能做出来”，而是“功耗也受控”。
- 让项目更像企业开发模式下的产品方案，而不是单纯竞赛 demo。
- 为后期做续航、低功耗待机和异常断电运行打基础。

风险提醒：

- 当前阶段不应与主闭环开发抢资源。
- 应放在主功能稳定之后再深入推进。

优先级：

- `中期规划`

## 7. 推荐主线方案与预期收益汇总

### 7.1 必做主线

- 24GHz 雷达验证与场景标定。
- 风险状态机。
- 事件层。
- 可解释风险分与证据链。
- 蜂鸣器 + 按钮确认闭环。
- 日志缓存机制。
- MQTT / HA 状态、事件与报告上报。

预期收益：

- 形成完整系统创新闭环。
- 项目从“采集显示 demo”升级为“边缘自治看护系统”。

### 7.2 高收益增强

- 压力垫。
- 继电器。
- ESP32-S3 Wi-Fi CSI。

预期收益：

- 压力垫负责降低误报。
- 继电器负责主动干预。
- CSI 负责隐私友好的人体活动增强感知。

### 7.3 中后期路线

- 低功耗优化。
- 18650 断电维持运行。
- 最小运行版本。
- 更高级的日志补传、系统审计和降级策略。

预期收益：

- 强化 ST 赛道适配性。
- 提高作品工程完成度和企业开发风格。

### 7.4 当前不建议主攻

- PIR 继续深挖。
- 各类视觉/热图方案。
- 重型黑盒 AI 识别。
- 当前阶段复杂故障感知体系。
- 高风险且强依赖外部生态的新主传感器。

预期收益：

- 避免项目发散。
- 保证一个月内能做出稳定、可验证、可答辩的系统。

## 8. 预期文章叙事

最终文章/答辩建议叙事如下：

1. 独居老人场景真正困难的不是单次跌倒识别，而是在隐私受限、网络不稳定、传感器不完美的真实家庭中，持续理解人的生活状态并可靠响应风险。
2. 本项目基于 STM32U5 构建隐私优先型边缘自治看护系统，不依赖普通摄像头。
3. 系统以 `24GHz 雷达 + MQ2 + BME280 + 本地交互 + MQTT/HA` 为基础，后续可引入 `ESP32-S3 Wi-Fi CSI` 作为增强模态。
4. 系统通过事件层、风险状态机、证据链和日志缓存机制实现可解释、本地自治和可扩展的照护闭环。
5. 后续进一步向低功耗、电池维持运行和最小运行版本演进，体现 ST 赛道的工程化方向。

## 9. 一句话总结

当前项目最合理的技术路线不是“继续堆更多传感器”，而是：

**围绕 24GHz 雷达主感知、环境风险辅助、事件层、风险状态机、日志缓存和本地自治闭环，做成一个隐私优先、可解释的边缘看护系统；再用 ESP32-S3 Wi-Fi CSI 替代视觉模块，并在后期把低功耗、18650 供电和最小运行版本纳入 ST 赛道特色演进方向。**
