# 作品报告更新稿

## 作品名称

**守望者：面向独居老人的隐私优先型边缘智能看护与智能家居联动系统**

## 摘要

针对独居老人居家看护中“隐私难保护、异常难确认、报警难闭环、断网难工作、家居难联动”的痛点，本作品设计并实现了一套以 STM32U5A5ZJ 为核心的 AI+IoT 边缘智能看护系统。系统采用“多模态感知 + 本地边缘 AI + 状态机安全闭环 + 云端智能复核 + 智能家居联动”的分层架构，在不依赖普通摄像头、不强依赖云端在线的前提下，实现环境安全、人体存在、活动趋势、主动求助、远程控制和本地告警的综合管理。与强依赖网络和云平台的传统方案不同，本系统将核心安全判断、确认流程和执行器响应放在本地完成，云端主要承担二次验证、摘要生成、远程展示和通知分发。

在感知侧，系统集成 BME280 温湿度/气压传感器、MQ 气体传感器、PIR 红外检测、Rd-03 V2 24GHz 毫米波雷达、SOS/ACK 按键、无源蜂鸣器、TFT 本地显示屏、四路继电器、ESP8266 MQTT 网关和 ESP32-S3 语音协处理模块。毫米波雷达通过 UART DMA 接收距离、能量门、运动评分、久静时间等非成像特征，既保留空间行为感知能力，又避免摄像头带来的隐私压力。MQ 传感器经过分压保护、滤波、基线跟踪和经验曲线换算，将模拟电压转化为更直观的 ppm 估算值。语音模块基于开源语音识别框架进行离线关键词识别，可将“救命”“我摔倒了”“确认报警”“取消报警”等老人侧自然语音转换为本地语义命令。TFT 屏幕实时展示温湿度、气体浓度、人体存在、雷达状态、风险等级和系统状态，继电器可联动低压灯具、排风等家庭设备。

在决策侧，STM32U5 运行统一状态机，覆盖 NORMAL、NOTICE、ACK_WAIT、ALARM、NO_RESPONSE、CLEARED 等状态，实现“异常检测-本地提醒-等待确认-超时升级-远程通知-告警解除”的闭环流程。系统同时加入本地轻量神经网络推理模块，使用 12 维环境、气体、雷达、人体存在和网络状态特征，经 12-8-6 MLP 输出场景类别、风险等级、置信度和异常评分，并作为状态机风险下限参与决策。因此，即使家庭 Wi-Fi、MQTT 服务或云端分析暂时不可用，系统仍可在本地完成环境检测、求助识别、风险判断、声光提醒、ACK 确认和继电器联动。该设计使作品不只是阈值报警器，而是具备边缘智能判断、离线友好运行、可解释风险证据和后续训练迭代能力的看护节点。

在通信和云端侧，ESP8266 将 STM32 串口状态帧与事件帧转换为 MQTT JSON 消息，上传至 Mosquitto、Home Assistant 和后端分析服务。云端服务根据传感器、状态机、边缘 AI 和事件日志进行二次分析，可生成中文风险摘要、通知建议和智能家居控制指令；远程端也可下发继电器、ACK、演示场景等命令。通知链路支持 Home Assistant 面板、Web Dashboard、PushPlus 微信推送，并可按配置扩展到短信、电话等触达方式，面向家属、社区和医院形成分级告警策略。系统形成“本地快速响应 + 云端智能复核 + 多级通知触达 + 家居执行反馈”的完整链路，适用于独居老人家庭、社区养老驿站、养老院房间和无摄像头敏感区域。

本作品当前形态定位为“可验证的 AIoT 集成原型系统”。其中 TFT 屏幕用于比赛现场和工程调试阶段直观展示本地状态，产品化后可替换为墙面终端、手机小程序、Home Assistant 面板、微信/短信通知或语音交互界面；继电器侧使用低压 LED 作为安全替代负载，用于证明云端命令、本地状态机和执行器之间的全链路控制能力，实际产品中可在安全隔离条件下扩展到照明、排风、提示灯、插座等家庭设备。该原型重点验证的不是单个传感器或单个屏幕，而是从“感知-判断-确认-告警-联动-记录-复核”的完整系统能力。

**关键词：** STM32U5；边缘 AI；独居老人看护；毫米波雷达；离线自治；语音识别；MQTT；Home Assistant；智能家居联动；多级通知；隐私保护

## 第一部分 作品概述

### 1.1 功能与特性

本作品面向独居老人居家安全场景，提供环境监测、人体存在感知、久静异常判断、主动求助、气体风险预警、本地声光提醒、TFT 状态显示、远程 MQTT 同步、云端 AI 分析、Home Assistant 展示和四路继电器联动能力。系统针对传统看护方案中“摄像头侵犯隐私、穿戴设备依从性差、人工巡检存在盲区、纯云端方案断网失效、单阈值报警误报率高”等痛点，以 STM32U5 为本地安全核心，即使网络暂时不可用，也能继续完成传感器采集、风险判断、蜂鸣器提醒、按键确认和本地执行器控制。系统强调“隐私优先”，不采集普通摄像头图像，而通过毫米波雷达、PIR、环境传感器和气体传感器形成非成像多模态感知。

### 1.2 应用领域

系统适用于独居老人家庭、社区养老驿站、养老院房间、康复看护空间和不适合安装摄像头的隐私区域。典型部署位置包括客厅、卧室、厨房门口和卫生间外侧。系统可用于日常环境监测、气体泄漏提醒、老人活动状态观察、长时间无响应提示、主动求助告警和智能家居安全联动。对于未来扩展，可将多个节点部署在不同房间，通过云端形成家庭级空间状态图和风险趋势分析。

建议配图：居家部署示意图。标注雷达朝向、传感器区域、继电器控制对象和远程看护端。

### 1.3 主要技术特点

系统采用多芯片异构协同架构：STM32U5A5ZJ 负责本地传感器融合、状态机、边缘 AI、TFT 显示、蜂鸣器和继电器；ESP8266 负责 UART-to-MQTT 网关；语音模块可通过独立 UART 接入语义命令；云端负责数据持久化、可视化和 AI 复核。该架构形成“STM32 毫秒级安全响应 + 语音/网关协处理 + 云端语义增强”的层次化智能体系，使系统既能作为离线自治看护节点运行，也能接入家庭自动化平台形成远程看护网络。软件采用 CubeMX + CLion + CMake 工程结构，按传感器、雷达、状态机、通信、显示、板级 IO、场景引擎和本地 AI 模块分层。雷达接收使用 USART3 DMA Receive-to-Idle，降低串口阻塞和丢帧风险；气体检测使用滤波与基线跟踪；AI_SAMPLE 日志可直接转为 CSV 和滑动窗口特征，为后续模型训练提供数据闭环。

### 1.5 主要创新点

1. 隐私优先的非成像看护：以毫米波雷达、PIR、环境和气体传感器替代普通摄像头，既获得人体存在、距离、活动和环境风险信息，又避免采集人脸、姿态图像和室内隐私画面。
2. 离线友好的本地自治安全闭环：STM32U5 不只是采集数据，而是在本地完成风险分级、ACK 等待、告警升级、蜂鸣器提示和继电器联动；云端只负责二次验证、远程展示和通知增强，断网时仍可保持核心安全能力。
3. MCU 侧轻量神经网络：在 STM32 上集成 12-8-6 MLP，将温湿度、气体、雷达、人体存在和网络状态融合为场景类别、风险等级、置信度和异常评分。
4. 规则兜底 + AI 增强：状态机采用安全融合策略，AI 可以提高风险等级，但不能压低 SOS、气体高危、ACK 超时等硬规则风险，兼顾智能性和安全确定性。
5. 雷达能力深度利用：不是只读取 OT2 有人/无人数字量，而是解析 Rd-03 V2 UART 的距离、区域、能量门、运动评分和久静时间，为空间行为分析和后续建模提供基础。
6. 全链路智能家居联动：通过 STM32、ESP8266、MQTT、Home Assistant 和继电器形成“云端指令-本地执行-状态反馈”的闭环；当前 LED 为安全演示负载，可等价替代照明、排风等家居执行对象。
7. 原型到产品的可迁移设计：TFT、LED 和底板是工程验证载体，系统架构已经将显示、执行器和云端接口解耦，产品化后可替换为 App、墙面中控、语音终端或安全隔离家电控制模块。
8. 可解释事件证据链：每次异常都带有风险来源、触发源、状态迁移、ACK 剩余时间、继电器状态和场景证据，便于家属、社区或维护人员复盘。
9. 数据驱动迭代闭环：AI_SAMPLE 日志记录原始传感器、雷达特征、状态机、场景引擎和 EdgeAI 输出，可转 CSV 和滑动窗口特征，为后续训练、评估和报告图表提供数据基础。
10. 多场景扩展能力：同一套节点可分析主动求助、久静无响应、气体风险、离线异常、远程家居控制、环境舒适度和多房间部署等场景，不局限于单一报警功能。
11. 分层告警与人机协同：系统支持本地蜂鸣器/屏幕提醒、语音/按键确认、云端摘要和远程联动，避免“检测到异常就立刻误报”的单级报警逻辑，形成更贴近真实家庭使用习惯的确认链路。
12. 离线语音求助入口：引入 ESP32-S3 语音协处理模块，将开源语音识别模型输出的“救命、我摔倒了、确认、取消”等语义命令接入 STM32 状态机，使老人不需要寻找手机或按钮也能触发求助和确认。
13. 多级通知触达：云端可通过 Home Assistant、Web Dashboard、PushPlus 微信推送，并按配置扩展短信、电话等渠道，将高风险事件按家属、社区、医院等层级分发，避免告警只停留在本地。

### 1.6 设计流程

项目按照“需求分析-硬件选型-引脚规划-CubeMX 配置-驱动接入-状态机搭建-通信联调-场景验收-AI 数据闭环-报告与演示固化”的流程推进。早期重点验证点灯、串口、I2C、ADC、GPIO、TFT 和 MQTT 链路；中期完成 BME280、MQ、PIR、Rd-03 雷达、蜂鸣器、继电器和 Home Assistant 联动；后期将多源数据统一进入状态机、场景引擎和本地边缘 AI，形成可演示、可解释、可训练的完整系统。

## 第二部分 系统组成及功能说明

### 2.1 整体介绍

系统由五层组成：感知层、边缘决策层、执行交互层、通信云端层和远程展示联动层。

感知层包括 BME280、MQ、PIR、Rd-03 V2 雷达、按键和语音输入。边缘决策层由 STM32U5 上的 SensorMvp、RadarFeatures、SceneEngine、EdgeAI 和 AppStateMachine 构成，对环境、气体、人体存在、雷达运动、久静时间、语音/按键事件进行融合。执行交互层包括 TFT、蜂鸣器、四路继电器和本地状态 LED。通信云端层由 ESP8266 网关、MQTT Broker、后端分析服务和数据库组成。远程展示联动层包括 Home Assistant、Web Dashboard、手机端通知和智能家居执行对象。

系统核心思想是“安全闭环在本地，智能增强在云端”。本地状态机保证即使没有网络也能响应；云端负责更强的语义分析、趋势记录、远程展示和联动编排。

#### 2.2.2 机械设计介绍

当前原型采用单底板展示结构，将主控、屏幕、传感器、继电器、电源和通信模块分区固定，便于演示、排线和排障。布局遵循三个原则：第一，雷达和 PIR 朝向活动区域，避免被线束和金属板遮挡；第二，MQ 传感器放在边缘通风区域，便于模拟气体/烟雾趋势；第三，TFT、按键和蜂鸣器面向用户，继电器和外部负载远离弱信号传感器。后续外壳设计可在当前底板上进行模块化封装，保留雷达窗口、气体通风孔、屏幕开窗和按钮外露位置。

需要说明的是，当前底板不是最终消费级外观，而是用于比赛展示、调试复现和模块化验证的工程样机形态。TFT 屏幕承担“本地状态可视化样例”的角色：它证明主控具备本地显示和人机提示能力，但最终产品并不必然使用该屏幕形态，可以根据应用场景替换为更大尺寸墙面屏、手机端页面、Home Assistant 卡片、语音播报或无屏低功耗节点。采用原型化开放结构的目的，是让评委能够直接看到各传感器、执行器和通信模块如何协同工作。

#### 2.2.3 电路各模块介绍

BME280 通过 I2C1 接入，地址为 0x76；MQ 传感器使用 ADC 采样，并通过分压保护 STM32 ADC 输入；Rd-03 V2 通过 USART3 接收 UART 数据帧，并保留 OT2 数字存在输出作为辅助信息；ESP8266 通过 USART2 与 STM32 通信，将本地 CSV 帧转换为 MQTT JSON；语音/麦克风模块通过 UART4 输入语义命令；TFT 使用 SPI1；无源蜂鸣器由定时器 PWM 驱动；四路继电器通过 GPIO 高电平触发，控制低压 LED/排风等演示负载。

电源方面，STM32 主板、传感器、ESP8266、继电器和外设需要统一地线；高电流模块优先使用独立 USB 或面包板电源供电，避免开发板 5V 输出过载。继电器演示负载只使用低压直流，不直接接入市电，保证调试安全。

继电器部分采用低压 LED 作为替代负载，是出于比赛现场安全性和可重复演示考虑。该连接方式已经覆盖真实产品中的关键技术链路：云端/本地命令下发、STM32 GPIO 输出、继电器吸合、负载状态变化和状态回传。若进入产品化阶段，只需在继电器输出端增加符合电气安全规范的隔离、保险和接线端子，即可扩展到照明、排风、提示灯或其他低压/安全隔离家居设备。

### 2.3 软件系统介绍

#### 2.3.1 软件整体介绍

固件采用裸机超级循环架构，主循环依次执行传感器更新、应用状态机更新、板级 IO 更新、串口调试命令处理、云端命令处理、本地语音命令处理、继电器自动化、事件上报、TFT 刷新、状态上报和 AI_SAMPLE 日志输出。模块划分如下：

| 模块 | 作用 |
| --- | --- |
| SensorMvp | 汇总 BME280、MQ、PIR、雷达状态 |
| Rd03/RadarFeatures | 雷达 UART 帧接收、距离门和运动特征解析 |
| AppStateMachine | 风险状态、ACK 等待、告警、清除和事件记录 |
| SceneEngine | 多场景解释，把传感器证据转为场景信号 |
| EdgeAI | 本地轻量神经网络，输出场景、风险、置信度 |
| BoardIo | 按键、蜂鸣器、继电器、LED 等板级输入输出 |
| CommWifi | STM32 与 ESP8266 通信、状态/事件/命令协议 |
| CommLocal | 语音模块本地 UART 命令接入 |
| StatusDisplay/TFT | 本地屏幕 UI 和状态刷新 |

#### 2.3.2 本地边缘 AI

系统新增 `EdgeAI` 模块，在 STM32U5 上运行轻量神经网络推理。模型输入为 12 维归一化特征，覆盖高温偏差、低温偏差、高湿偏差、气体 ppm、气体基线变化、融合人体存在、雷达有效性、雷达距离、活跃距离门数量、雷达运动评分、久静时间和网络状态。模型结构为 `12 inputs -> 8 hidden neurons -> 6 scene classes`，输出 NORMAL、ENV_COMFORT、GAS_RISK、STILLNESS_RISK、ACTIVITY_ANOMALY、SYSTEM_CONTEXT 六类场景，并给出 0-3 级风险、置信度和异常评分。

状态机不会盲目服从 AI，而是采用“AI 只能提高风险，不能压低硬规则”的安全策略：SOS、气体高危、语音高危、ACK 超时等硬规则优先；当 EdgeAI 输出高置信异常时，作为风险下限参与融合。这种设计兼顾了神经网络的模式识别能力和安全系统的确定性。

#### 2.3.3 场景引擎与状态机

状态机负责系统动作，场景引擎负责解释“为什么”。例如，气体 ppm 上升会触发 GAS_RISK；雷达存在但长时间无明显运动会触发 STILLNESS_RISK；本地 SOS 或语音高危会进入 ACK_WAIT；超时未确认后进入 ALARM 或 NO_RESPONSE。每个事件都会记录事件编号、触发源、风险等级、继电器状态和确认剩余时间，便于串口、MQTT、面板和报告截图复盘。

#### 2.3.4 通信与云端

STM32 以轻量 CSV 帧向 ESP8266 上报状态和事件，ESP8266 负责转换为 MQTT JSON。云端可订阅状态、事件、继电器响应和 AI 分析结果，也可下发继电器、ACK、清除、演示场景和调试指令。Home Assistant 通过 MQTT 实体展示温湿度、气体、人体存在、风险等级和告警状态，并可进一步对接智能灯、排风、插座等家庭设备。

云端分析采用“确定性规则引擎 + 大模型语义增强”的双重验证思路：规则引擎先给出可解释的风险底线，大模型在异常、求助、气体风险或复合场景下生成自然语言摘要、风险原因和处置建议。系统策略上坚持 `final_risk >= rule_risk`，也就是 AI 可以帮助理解和补充，但不能把硬规则判定的风险降级。这使作品同时具备工程实时性和展示表达力：本地 STM32 保证异常秒级响应，云端 AI 则把“传感器数值”转换成家属和社区人员能理解的话，并进一步驱动分级通知、自动化联动和事件复盘。

#### 2.3.5 数据采集与训练闭环

固件周期性输出 `[AI_SAMPLE]` 机器可读日志，包含传感器原始值、雷达特征、状态机状态、场景引擎结果、本地 EdgeAI 输出和人工标签。串口调试命令可切换 `env / walk / fall / still / gas / voice / idle` 等标签。配套工具可将日志转换为 CSV，并生成滑动窗口特征，用于后续训练、评估、混淆矩阵和模型权重替换。该闭环使作品具备“先有可运行智能原型，再用真实场景数据持续优化”的工程路线。

### 3.4 典型演示场景

#### 场景一：日常看护

系统处于 NORMAL 状态，持续采集温湿度、气体、PIR 和雷达数据。TFT 显示当前环境和人体存在状态，ESP8266 将数据同步到云端。云端面板展示趋势和当前风险，家属可远程查看。

#### 场景二：气体异常与排风联动

MQ ppm 估算值超过阈值后，状态机进入 NOTICE 或 ALARM，蜂鸣器发出提醒，TFT 显示风险状态，云端收到事件并可自动打开继电器控制的排风/提示设备。无标准气体时，可通过调试指令模拟 ppm 上升完成安全演示。

#### 场景三：老人主动求助

老人按下 SOS 或通过语音模块发出高危求助，STM32 进入 ACK_WAIT，蜂鸣器提醒并等待 ACK。若用户确认安全，系统解除告警；若超时无响应，则升级为 ALARM/NO_RESPONSE，并通过 MQTT/云端通知远程看护端。

#### 场景四：久静与活动异常

Rd-03 V2 持续检测到人体存在但运动评分较低、久静时间持续增长时，SceneEngine 和 EdgeAI 会给出久静或活动异常提示。系统先进入低级风险提醒，避免立即误报；若叠加其他信号或无响应，则逐步升级。

#### 场景五：远程家居控制

远程端通过 MQTT 下发继电器命令，STM32 控制四路继电器开关，反馈继电器状态。该能力可用于灯光、排风、提示灯、插座等低压或安全隔离设备，是后续接入米家/Home Assistant 自动化的基础。

当前演示中使用两路低压 LED 作为继电器负载，目的不是把 LED 当作最终产品功能，而是用可见、低风险、可反复操作的方式展示云端到本地执行器的闭环控制。真实部署时，该链路可替换为排风扇、床头灯、紧急提示灯或经安全隔离的家电控制设备。

## 第四部分 总结

### 4.1 可扩展之处

后续可从四个方向扩展：第一，基于真实 AI_SAMPLE 数据训练更稳定的本地模型，将当前 12-8-6 MLP 权重替换为实测模型权重；第二，完善雷达可视化平台，把 32 个距离门能量、运动评分和距离变化绘制为二维热力图，用于空间活动建模；第三，加入多节点部署，将客厅、卧室、厨房等区域数据融合成家庭级状态图；第四，进一步接入云端大模型和智能家居生态，实现“异常解释-通知建议-执行联动”的自动化闭环。

### 4.2 心得体会

本项目的核心价值不在于单个传感器读数，而在于把多源感知、边缘判断、本地交互、远程同步、AI 复核和家居执行组织成一个稳定闭环。开发过程中，最容易低估的是硬件引脚、供电、串口方向、雷达 DMA 接收和真实场景误报等工程问题。通过反复核对 Nucleo 手册、器件文档和实际日志，项目逐步形成了规范 pinmap、状态机验收、协议文档、AI 数据采集和报告交付文档。

作品也体现了 AI+IoT 的工程落点：AI 不是孤立模型，而是嵌入在一个能执行、能反馈、能记录、能解释的物联网闭环中。本地轻量模型负责快速、低延迟、隐私优先的初步判断；云端模型负责更强的语义理解、趋势总结和通知建议；确定性状态机负责兜底安全。这样的分层设计既避免了纯规则系统扩展性不足，也避免了纯 AI 系统不稳定和不可解释的问题。

当前原型已经具备完整演示能力，后续重点是继续采集真实场景数据、优化雷达特征和本地模型、提高误报抑制能力，并完成更稳定的机械固定和外壳设计。最终目标是把作品从“可运行原型”推进为面向真实居家环境的低成本、低功耗、隐私友好型智能看护节点。
