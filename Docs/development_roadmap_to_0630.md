# 6.30 收尾开发路线与分工计划

更新时间：2026-06-16

## 1. 目标

在 `2026-06-30` 前，将当前项目收敛为一个可稳定演示的在线 IoT 闭环系统。

具体模块拆解、CRUD、重构范围、人员职责和每日交付计划见 `Docs/implementation_breakdown_to_0630.md`。

当前版本不再以“先把人体异常检测做准”作为第一目标，而是优先完成以下 3 个展示场景：

1. 主动求助 / 模拟跌倒后的闭环响应
2. 长时间静止无响应的异常确认与升级
3. 断网或市电异常下的本地自治与日志补传

## 2. 总体技术路线

### 2.1 主控侧定位

STM32 主控负责：

- 本地输入采集
- 事件生成
- 状态机推进
- 本地确认
- 本地提示与执行
- 本地日志缓存
- 状态与事件上报

### 2.2 云端侧定位

云端负责：

- MQTT 数据接收与整理
- 事件与日志存储
- Home Assistant 基础实体接入
- 新展示面板与控制面板开发
- 跨设备联动展示
- 离线恢复后的日志展示

## 3. 主控开发计划

### 3.1 微调即可复用的部分

- 传感器采集框架
- `CommWifi` 状态上报与继电器协议
- TFT 驱动与显示调度框架
- 现有 ESP8266 MQTT 网关链路

### 3.2 必须新增的业务层

- 事件模型
- 三场景共用状态机
- 遥控触发接口
- 按钮确认接口
- 本地动作执行层
- 本地日志缓存层
- 离线缓存与恢复补传接口

### 3.3 主控优先级

#### P0

- 完成统一事件枚举与状态流转
- 完成遥控触发接入场景一
- 完成确认、超时升级、清除闭环
- 完成本地日志记录
- 完成离线状态与恢复补传接口

#### P1

- 继电器动作编排
- 蜂鸣器与语音提示策略
- TFT 页面场景化改造

#### P2

- 低功耗模式分层
- 备用供电模式预留
- 检测能力增强

## 4. 云端开发计划

### 4.1 当前可复用部分

- Mosquitto
- `analysis_service` ingest 与数据库框架
- Home Assistant 基础 MQTT 实体
- 继电器 MQTT topic 结构

### 4.2 必须新增的部分

- 事件中心或事件 topic
- 最近事件与告警记录展示
- 三场景专用展示逻辑
- 新展示面板
- 新控制面板
- HA 自动化与米家联动展示

### 4.3 展示面板要求

展示面板是比赛演示主视图，要求：

- 风格更强，视觉上要 `fancy`
- 重点展示当前状态、最近告警、设备在线状态、场景联动结果
- 能一眼看出当前处于哪个场景、风险是否升级、是否已确认
- 能突出“在线 IoT 闭环”而不是单纯传感器列表
- 应保留适度动画、颜色分级、状态卡片和时间线感

建议展示内容：

- 当前总状态
- 当前风险等级
- 当前场景名称
- 最近一次异常事件
- 用户确认状态
- 继电器状态
- 米家联动状态
- 网络在线/离线状态
- 离线补传结果
- 近期日志时间线

### 4.4 控制面板要求

控制面板不追求复杂，而是服务于你主动操作演示。

要求：

- 界面简洁
- 按钮少而明确
- 支持手动触发场景、清除状态、控制继电器
- 支持你在现场快速切换演示流程
- 不把控制逻辑堆进 fancy 展示面板里

建议控制项：

- 触发场景一
- 触发场景二
- 模拟离线/恢复
- 用户确认
- 清除当前报警
- 继电器 1 开关
- 继电器 2 开关

说明：

- 展示面板与控制面板建议分离
- 展示面板面向评委观看
- 控制面板面向演示人员操作

### 4.5 云端优先级

#### P0

- 定义事件存储结构
- 梳理三场景所需的云端字段
- 打通最近事件与状态展示

#### P1

- 开发 fancy 展示面板
- 开发简洁控制面板
- 接入 HA 自动化和米家联动展示

#### P2

- 日志查询增强
- 更复杂的统计图和长期分析
- 检测增强结果展示

## 6. 明确不作为当前第一优先级的事项

- 高精度跌倒识别
- 精确位置变化检测
- 房间精细标定
- 开放式语音对话
- 重型大模型主闭环控制

## 7. 一句话总结

到 `2026-06-30` 前，主控侧新增业务层、云端侧新增展示与控制面板，整体目标是把项目做成一个围绕三场景运行的在线 IoT 闭环展示系统。
