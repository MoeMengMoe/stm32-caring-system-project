# AI+IoT 路线说明

更新时间：2026-07-06

## 1. 项目定位

本项目不是单个传感器报警器，而是一个老人居家场景下的 AI+IoT 联动节点：

```text
多传感器采集
  -> 本地规则状态机
  -> 本地联动执行
  -> 云端状态汇聚
  -> 本地 AI / 云端 AI 分层增强
```

当前 STM32 侧的规则状态机是 AI 之前的地基。它负责稳定采集、打时间线、生成事件、完成 ACK/告警/继电器闭环。后续 AI 不直接替代这个地基，而是在它之上做更高层判断。

## 2. 当前已经能产生的数据

STM32 当前可提供：

- BME280：温度、湿度、气压。
- MQ：AO mV 调试链路、ppm 估算值、基线和增量。
- Rd-03 V2：有人/无人、距离、zone、peak gate、energy sum、motion score、occupied/still seconds。
- PIR：人体活动数字量。
- App 状态：state、scenario、risk、ack_remaining_ms。
- 本地联动：蜂鸣器、继电器状态、SOS/ACK 输入。
- 云端链路：状态帧 `S`、事件帧 `E`、继电器命令 `C/R`、演示命令 `D`。

这些数据已经足够支撑后续“多模态居家异常识别”的训练样本采集。

## 3. 本地 AI 计划

本地 AI 的职责是低延迟、断网可用、保护隐私：

```text
传感器时间窗
  -> 特征提取
  -> 轻量模型
  -> risk_hint / scenario_hint
  -> AppStateMachine 二次确认
```

建议优先做三个轻量模型方向：

1. 雷达异常静止模型  
   输入 `distance_cm / zone / motion_score / occupied_seconds / still_seconds / energy_sum`，输出久静、离床、异常停留等提示。

2. 环境异常模型  
   输入 `temperature / humidity / gas_ppm_est / gas_delta_mv / pressure`，输出闷热、烟雾/可燃气、环境突变等提示。

3. 规则融合模型  
   输入多个传感器和当前 state，输出 `risk_hint 0-3`，但最终执行仍交给状态机，避免模型直接控制继电器或告警。

第一版本地 AI 可以先不上神经网络，使用可解释模型或小型决策树；后续再考虑 STM32Cube.AI / TFLite Micro。

## 4. 云端 AI 计划

云端 AI 的职责是更强的上下文理解、历史趋势分析和用户解释：

```text
MQTT 状态流 + 事件流
  -> 数据库存储
  -> 云端 AI 分析
  -> 风险摘要 / 建议 / 自动化策略
  -> Home Assistant / Web Dashboard
```

云端 AI 可做：

- 日常行为模式学习：例如老人通常活动时间、夜间静止时长、厨房/卧室区域使用规律。
- 异常解释：把多个传感器变化转成自然语言，比如“长时间静止且湿度/气体无异常，更像休息；雷达距离突变且无 ACK，需关注”。
- 告警降噪：结合历史和多传感器，减少单一传感器误报。
- 联动策略建议：建议打开灯、通知家属、触发语音询问，而不是直接替代本地安全规则。

## 5. 近期执行顺序

比赛近期建议顺序：

1. 先稳定本地状态机闭环：SOS、久静、气体风险、离线自治。
2. 把状态帧和事件帧持续上传，保证云端有完整时间线。
3. 保存典型场景日志，形成训练/调参数据集。
4. 云端先做规则增强和可视化时间线。
5. 再接入 AI：先解释和建议，后做风险辅助评分。

## 6. 重要边界

- AI 输出先作为 `risk_hint`，不直接驱动继电器、蜂鸣器或清除告警。
- 本地状态机保留最终执行权。
- 所有 AI 判断必须可回退到规则模式。
- 训练前先积累真实日志，不凭空训练。
- 视觉模块后续只做辅助验证，不作为当前 MVP 的唯一核心。

## 7. 场景路线与采样日志

场景优先级、当前可行性、后续 AI 接入方式见 `Docs/scenario_detection_catalog.md`。

当前固件会周期输出 `[AI_SAMPLE]` 日志，作为后续本地/云端 AI 的统一采样入口。该日志包含环境、气体、雷达、状态机和风险等级字段，用于把“现场实验”沉淀成可分析的数据集。
