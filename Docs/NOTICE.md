# NOTICE

## AI 修改边界

- 不直接修改 `.ioc`。
- 不修改 HAL/CubeMX 自动生成区。
- 不在 `main.c` 堆积业务逻辑。
- 每次只改一个明确模块或一组文档骨架。
- 生成的新接口需要说明调用关系。

## 工程边界

- MVP 阶段优先完成闭环，不引入 Edge AI、自制 PCB、复杂低功耗、多节点部署。
- 传感器、显示、告警、通信、风险判断需要模块化。
- `Docs/pinmap.md` 是引脚分配、CubeMX 配置与接线方式的唯一权威来源。
- 任何引脚、外设实例、Arduino/Zio 逻辑编号、实物丝印、供电或接线变化必须在同一次提交中更新 `Docs/pinmap.md`。
- 任何引脚配置或接线结论必须先核对 ST 官方板卡用户手册、对应板卡修订版原理图和 MCU 复用功能资料，不允许仅凭 CubeMX、经验或记忆下结论。
- 实物接线说明必须优先写连接器编号、连接器针脚号、板子朝向、列/行位置和实物可见丝印。手册中的 Zio `Dxx` 逻辑编号只能作为辅助信息，禁止单独用于指导接线。
- 如果焊桥、板卡修订版、复用冲突或实物位置尚未核对清楚，必须标记为“待核对”，不得指导接线。
- 通信字段变更必须同步到 `Docs/protocol.md`。
