# Rd-03 V2 雷达使用与开发说明

本文档记录本项目对安信可 Rd-03 V2 广覆盖人体微动毫米波传感器的理解、接线、协议使用方式和后续开发计划。

## 1. 为什么不能只把它当作 GPIO 传感器

Rd-03 V2 不只是一个“有人时输出高电平”的模块。它能够：

- 检测人体运动、微动和静止存在。
- 上报有人/无人状态。
- 上报目标与雷达之间的直线距离，单位为厘米。
- 在上报模式下输出 32 个距离门的能量值。
- 配置最小/最大探测距离、目标消失延迟、运动触发门限、运动保持门限和微动门限。
- 自动扫描环境噪声并生成门限。
- 检测电源干扰。

因此，本项目将 UART 数据作为雷达主数据源，将 `OT2` 高低电平作为快速兜底和交叉检查。

## 2. 模块端引脚含义

模块端必须按 PCB 丝印识别，不要只按针脚序号判断。

| Rd-03 V2 丝印 | 方向，以雷达为主体 | 功能 | 本项目连接 |
| --- | --- | --- | --- |
| `3V3` | 输入 | 3.3V 供电 | NUCLEO `3V3` |
| `GND` | - | 地 | NUCLEO `GND` |
| `RX` | 输入 | 接收配置命令 | NUCLEO `CN10 pin 32 / 黑色排母外侧列倒数第二孔 / PB10 / USART3_TX` |
| `OT1` | 输出 | 串口数据输出，部分官方表格写作 `TX` | NUCLEO `CN10 pin 34 / 黑色排母外侧列最下面孔 / PB11 / USART3_RX` |
| `OT2` | 输出 | 根据检测结果输出高低电平 | NUCLEO `A4 / PC1 / RD03_OUT` |

完整接线：

```text
Rd-03 3V3 -> NUCLEO 3V3
Rd-03 GND -> NUCLEO GND
Rd-03 RX  <- NUCLEO CN10 pin 32 / 黑色排母外侧列倒数第二孔 / PB10 / USART3_TX
Rd-03 OT1 -> NUCLEO CN10 pin 34 / 黑色排母外侧列最下面孔 / PB11 / USART3_RX
Rd-03 OT2 -> NUCLEO A4  / PC1  / RD03_OUT
```

`D36/D35` 是 ST 手册中的 Zio 逻辑编号，不会印在板子正面。实物接线时不要寻找 `D36/D35`，应按照 `CN10 pin 32/pin 34` 和连接器中的实际位置定位。

`CN10 pin 32/pin 34` 是偶数脚，位于黑色 `CN10` 排母靠板边、靠金色 ST Morpho 排针的外侧列。靠 MCU 的内侧列最下面两个孔是 `pin 31/pin 33`，不是本项目需要的 USART3 引脚。

## 3. CubeMX 配置

USART3：

- Mode：`Asynchronous`
- Baud rate：`115200`
- Word length：`8 Bits`
- Parity：`None`
- Stop bits：`1`
- Hardware flow control：`None`
- `PB10`：`USART3_TX`
- `PB11`：`USART3_RX`
- `USART3_RX`：使用 `GPDMA1 Channel 1`
- DMA Request：`GPDMA1_REQUEST_USART3_RX`
- DMA Direction：`Peripheral to Memory`
- DMA Source increment：`Fixed`
- DMA Destination increment：`Incremented`
- DMA Data width：`Byte / Byte`
- DMA Mode：`Normal`，由 `HAL_UARTEx_ReceiveToIdle_DMA()` 在 `IDLE/TC` 事件后自动续接
- 中断：启用 `GPDMA1_Channel1_IRQn` 和 `USART3_IRQn`

OT2：

- `PC1`：`GPIO_Input`
- User Label：`RD03_OUT`
- Pull-up/Pull-down：`Pull-down`

当前 `.ioc` 已满足以上配置，不需要更换 MCU 引脚。对于本项目的 `MB1549-U5A5ZJQ-C04` 实物，官方原理图显示 `SB62` 已装配，因此 `PB10` 可从黑色 Zio 排母 `CN10 pin 32` 使用。

## 4. 串口协议要点

Rd-03 V2 使用 TTL 串口、小端字节序，默认参数为 `115200 8N1`。

### 4.1 配置命令帧

```text
帧头: FD FC FB FA
长度: 2 字节，小端
数据: 命令字 + 命令值
帧尾: 04 03 02 01
```

下发其他命令前必须先进入命令模式。官方协议建议：

1. 发送一次打开命令模式命令。
2. 等待约 100 ms，并清空串口缓存。
3. 再次发送打开命令模式命令。
4. 下发配置命令。
5. 关闭命令模式，恢复人体检测。

### 4.2 二进制上报模式

本项目启动时会将雷达切换到上报模式：

```text
帧头: F4 F3 F2 F1
长度: 2 字节，小端
结果: 1 字节，有人/无人
距离: 2 字节，小端，单位 cm
能量: 32 个距离门，每个 4 字节
帧尾: F8 F7 F6 F5
```

驱动位置：

```text
Modules/sensor/rd03_v2.c
Modules/sensor/rd03_v2.h
```

当前驱动解析：

- `presence`：雷达 UART 有人/无人状态
- `distance_cm`：目标距离
- `gate_energy[32]`：各距离门能量
- `frame_count`：有效上报帧计数
- `rx_byte_count`：STM32 收到的雷达 UART 总字节数
- `init_rx_byte_count`：初始化和配置命令阶段收到的 UART 字节数
- `open_command_ack_ok`：雷达是否确认打开命令模式
- `report_mode_ack_ok`：雷达是否确认切换到上报模式
- `close_command_ack_ok`：雷达是否确认退出命令模式
- `header_sync_count`：识别到上报帧头的次数
- `invalid_length_count`：非法数据长度次数
- `invalid_footer_count`：帧尾不匹配次数
- `dma_event_count`：USART3 RX DMA 触发接收事件的次数
- `dma_restart_count`：Receive-to-Idle 接收重新启动次数
- `auto_reinit_count`：连续一段时间没有收到任何 UART 字节后，驱动自动重新发送配置命令的次数
- `last_rx_tick`：最近一次收到 Rd-03 UART 字节的系统 tick
- `rx_overflow_count`：软件接收环形缓冲区溢出次数，正常验收应保持为 `0`
- `uart_error_count / last_uart_error`：USART3 非超时错误计数和最近错误码
- `last_update_tick`：最近有效帧时间

## 5. 当前项目使用方式

`SensorMvp_Update()` 每次超级循环调用 `Rd03V2_Update()`，持续接收并解析雷达数据。

当前版本已经移除运行期轮询接收。初始化阶段仍使用阻塞接收等待配置 ACK；配置完成后，`USART3_RX` 进入 `GPDMA1 Channel 1 + Receive-to-Idle` 接收。DMA 回调只把新增字节搬入软件环形缓冲区，`SensorMvp_Update()` 再调用 `Rd03V2_Update()` 在主循环中解析协议帧。这样即使 TFT 刷新、USART1 日志或其他任务短暂占用主循环，也不容易因为硬件 FIFO 来不及读取而丢失雷达字节。

每 500 ms，检测层会组合以下人体存在来源：

```text
PIR 有人
或 Rd-03 OT2 为高
或 Rd-03 UART 上报有人
=> presence = 1
```

调试日志会包含：

```text
rd03_ot2
radar_valid
radar_presence
radar_cm
```

其中：

- `rd03_ot2`：GPIO 高低电平。
- `radar_valid`：是否至少收到过一帧合法 UART 上报。
- `radar_presence`：UART 上报的有人/无人状态。
- `radar_cm`：UART 上报的目标距离。

每 2 秒还会输出一组专门用于验收 UART 协议的日志：

```text
[RADAR] valid=1 frames=123 rx_bytes=20480 dma_evt=240 reinit=0 rx_ovf=0 presence=1 distance_cm=85 peak_gate=8 peak_gate_cm=80 peak_energy=4567
[RADAR_E] g00=... g01=... g02=... g03=... g04=... g05=... g06=... g07=...
[RADAR_E] g08=... g09=... g10=... g11=... g12=... g13=... g14=... g15=...
[RADAR_E] g16=... g17=... g18=... g19=... g20=... g21=... g22=... g23=...
[RADAR_E] g24=... g25=... g26=... g27=... g28=... g29=... g30=... g31=...
```

其中 `frames` 应持续递增，`distance_cm` 应随目标距离变化；每个距离门长度为 `10 cm`，所以 `peak_gate_cm` 是峰值距离门对应的近似距离。距离门能量是相对能量值，不应直接解释为人体活动强度或风险等级。

尚未收到合法帧时会输出：

```text
[RADAR] valid=0 rx_bytes=0 init_rx=0 dma_evt=0 dma_restart=1 reinit=1 last_rx_age_ms=6000 rx_ovf=0 ack=0/0/0 header_sync=0 bad_len=0 bad_footer=0 uart_err=0 last_err=0x0
```

诊断含义：

- `init_rx=0` 且 `rx_bytes=0`：启动和运行阶段都没有收到任何字节。
- `ack=1/1/1`：雷达已经确认打开命令模式、设置上报模式和关闭命令模式。
- `ack` 不完整：至少一条配置命令未被确认，需要结合 `init_rx` 判断是 RX 链路还是 TX 链路问题。
- `rx_bytes` 增加但 `header_sync=0`：可能仍是运行模式文本，或配置命令没有到达雷达。
- `header_sync` 增加但没有合法帧：可能存在丢字节、串口参数错误或协议不匹配。
- `bad_len/bad_footer` 增加：收到的帧不完整或被破坏。
- `dma_evt` 持续增加：USART3 RX DMA 正在接收雷达字节。
- `dma_restart` 大于 `0`：Receive-to-Idle 接收已经启动；正常运行中可能随 IDLE/TC 事件增加。
- `reinit` 增加：驱动判断超过 5 秒没有收到 UART 字节，已经自动重新发送 open/report/close 配置命令。
- `last_rx_age_ms` 持续增加：距离最近一次收到雷达 UART 字节已经过去的毫秒数；如果很大且 `rx_bytes` 不增长，优先检查雷达电源、共地和 `OT1 -> PB11` 接线。
- `rx_ovf` 增加：软件环形缓冲区被写满，说明主循环处理速度仍不够，需要降低日志量、减少 TFT 阻塞或增大缓冲区。

## 6. 上板验收步骤

1. 断电后按照本文档重新检查 `RX / OT1 / OT2` 三根线。
2. 烧录最新 STM32 固件。
3. 打开 USART1 调试串口 `COM6`，参数 `115200 8N1`。
4. 上电后确认出现：

```text
[INFO] rd03 config ack open=1 report=1 close=1 init_rx=...
```

5. 等待并观察：

```text
[RADAR] valid=1
```

6. 人靠近和离开雷达，检查：

- `radar_presence` 是否变化。
- `radar_cm` 是否随距离变化。
- `rd03_ot2` 是否与 UART 状态大体一致。
- `[RADAR]` 中的 `frames` 是否持续递增。
- `[RADAR_E]` 中的距离门能量是否随目标位置和动作发生变化。

7. 将实际结果记录到 `Docs/debug_report.md`。

## 7. 当前验收结果

`COM6-115200.log` 已完成上报数据验收：`valid=1`、帧计数递增、目标距离变化，并且 `g00~g31` 的距离门能量均有输出。详细统计见 `Docs/debug_report.md`。

该日志早于最新 ACK 诊断固件，因此仍建议再保留一次包含 `rd03 config ack open=1 report=1 close=1` 的启动短日志，作为双向命令确认的补充证据。

## 8. 后续建议

- 使用官方上位机在实际安装环境中生成门限，不直接照搬默认门限。
- 根据卧室、客厅等场景设置最大探测距离和目标消失延迟。
- 在风险模块中使用“人体存在持续时间”和“距离变化”，不要只使用瞬时有人/无人。
- 后续可使用距离门能量判断干扰、活动强度和异常静止，但在真实数据采集完成前不要过早定义规则。
- 最终安装时固定雷达方向，避开风扇、窗帘、空调和强反射平面。
