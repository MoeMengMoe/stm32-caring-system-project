## 作品名称

隐私优先型边缘自治独居看护系统

## 摘要

本作品面向独居老人居家安全场景，设计并实现了一套以 STM32U5 为核心的低功耗、隐私友好型边缘自治看护系统。系统不依赖普通摄像头，而是通过 BME280 环境传感器、MQ 气体传感器、PIR 人体活动检测、Rd-03 V2 24GHz 毫米波雷达、本地按钮、蜂鸣器、继电器、TFT 显示屏、ESP8266 MQTT 网关、服务器分析服务和 Web/ Home Assistant 展示面板，构建“异常检测-本地提醒-用户确认-超时报警-远程通知-日志留存”的完整闭环体系。老人发生跌倒、主动求助或疑似长时间无响应时，系统先在本地检测异常并提示确认；若用户确认安全则解除告警，若超时未确认则升级为高风险报警。

在嵌入式端，STM32U5 负责多源传感器采集、雷达 UART DMA 接收、气体读数估算、人体存在融合、风险状态机、事件日志、TFT 本地显示、蜂鸣器提示和继电器联动。系统以 2 秒周期向 ESP8266 发送环境参数与风险状态，在关键状态变化时发送事件帧；ESP8266 将 CSV 串口帧转换为 MQTT JSON，并支持云端演示命令和继电器命令回传。服务器侧由 Mosquitto、分析服务、SQLite 数据库、展示面板和 Home Assistant 组成，能够保存状态与事件，展示温湿度、气体、人体存在、风险等级、最近事件、告警闭环和继电器状态；分析服务还能依据风险等级生成家属、社区、医院三级通知建议，并通过 PushPlus 向微信、短信、电话等配置渠道推送告警信息。云端接入大模型，对实时状态数据进行 AI 分析，输出风险评分、一句话摘要和通知建议，并驱动告警自动化；本地侧由 STM32 状态机、雷达特征层和 ESP32-S3 语音识别模型先行判断，云端大模型再进行复核，形成“本地快速响应 + 云端 AI 复核”的双重验证机制。系统通过 Home Assistant/MQTT 与智能家居生态兼容，可进一步桥接米家设备，配合多路继电器实现灯光、排风、插座等家庭电器联动和远程操作。

当前作品重点展示三类典型场景：跌倒/主动求助后的确认与报警，长时间静止无响应的异常确认，断网情况下的本地自治与恢复补传。系统通过非成像雷达和环境传感器降低隐私风险，通过 STM32 本地状态机降低对网络和云端的依赖，通过 Home Assistant 与 PushPlus 把本地事件扩展为亲属、社区、医院可接收的远程处置链路，通过事件帧、AI 摘要和日志机制提高可解释性和可追溯性。云端大模型只参与分析、摘要和通知建议，不直接替代本地安全闭环；当模型给出的风险更高时，系统采用更高风险等级，当模型判断较低时也不会降低本地规则风险。已验证能力包括 BME280 采集、MQ 模拟量采集、PIR 输入、Rd-03 V2 UART 距离和 32 个距离门能量解析、STM32 状态发送、ESP8266 到 MQTT/HA 链路、本地 SOS/ACK 与蜂鸣器闭环等；正式展示时配套放置串口日志、MQTT 消息、Home Assistant 面板、AI 分析摘要和 PushPlus 通知截图，证明闭环链路可追踪、可复现。

## 第一部分 作品概述

### 1.1 功能与特性

系统具备环境监测、人体存在感知、跌倒/求助事件触发、本地风险判断、告警提醒、用户确认、远程展示、多级通知、智能家居联动和事件记录能力。BME280 采集温湿度和气压，MQ 模块采集气体模拟量并估算 ppm，PIR 与 Rd-03 V2 雷达共同判断人体存在；雷达 UART 还可提供目标距离、32 个距离门能量、区域编号、运动评分和久静时间，测量范围覆盖环境安全、人体存在、空间距离和活动状态。STM32U5 内部运行统一状态机，支持 NORMAL、ACK_WAIT、ALARM、NO_RESPONSE、CLEARED 等状态，并围绕“检测到异常-本地提醒-等待确认-超时报警-远程通知”形成闭环。TFT 显示本地状态，蜂鸣器和继电器提供现场反馈，ESP8266 通过 MQTT 将状态和事件同步至 Home Assistant 与服务器，服务器再通过 PushPlus 将高风险事件推送给家属、社区或医院联系人；四路继电器支持远程和本地联动控制，可用于控制低压演示灯、排风、照明或经安全隔离后的家庭电器。

### 1.2 应用领域

本作品适用于独居老人家庭、社区养老驿站、养老院房间、康复看护空间和无摄像头敏感区域。对于卧室、卫生间门口、客厅等隐私要求高的场景，系统可使用毫米波雷达、环境传感器和按钮替代普通摄像头，持续判断“是否有人、是否久静、环境是否异常、是否需要确认”。在网络不稳定或家庭网关暂时离线时，STM32 仍可保持本地显示、提示、确认和继电器联动，适合作为低成本、可扩展、可本地自治的居家安全节点。

图片建议：放“居家部署示意图”。效果为房间平面图中标出主机、雷达探测扇区、气体传感器、TFT/蜂鸣器、路由器和家属端面板。制作方法：用 PPT 简化房间平面图，叠加半透明扇形雷达覆盖区域和 MQTT 远程箭头。

### 1.3 主要技术特点

系统采用“STM32 本地自治 + MQTT 远程同步 + 云端 AI 分析 + Home Assistant 友好界面 + PushPlus 多级触达 + 智能家居联动”的分层架构。嵌入式端使用 STM32U5A5ZJ、HAL、CMake 和模块化 C 代码，将传感器采集、业务状态机、通信、显示、板级 IO 分离，具备低功耗芯片平台和后续电池/最小运行模式扩展基础。雷达接收采用 USART3 RX DMA + Receive-to-Idle，避免 TFT 刷新和串口日志造成丢帧；通信协议采用 STM32 到 ESP8266 的轻量 CSV，ESP8266 到 MQTT 的 JSON，兼顾主控资源和服务器可读性，状态约 2 秒上报一次，关键事件即时上报。风险判断采用本地状态机、雷达特征模型和语音识别模型先行处理，云端规则引擎与大模型进行二次分析；大模型输出 `cloud_risk`、`risk_score`、`summary` 和通知建议，且合并策略不允许降低本地风险等级。服务器侧使用 Mosquitto、SQLite、分析服务和 Web 面板保存与展示状态、事件和告警结果，并按风险评分生成 family、community、hospital 三类通知决策，由 PushPlus 发送到微信、短信、电话等配置渠道。

### 1.5 主要创新点

1. 低功耗、隐私友好：以 STM32U5 和非成像毫米波雷达为核心，不使用普通摄像头。
2. 完整闭环：将跌倒、求助、久静和环境异常统一到“检测-提醒-二次确认-报警升级”的状态机。
3. 云端同步：环境参数、人体存在、风险等级和事件日志上传到 Home Assistant 与 Web 面板。
4. 云端 AI：接入大模型进行实时云端分析，生成风险评分、实时摘要和通知建议。
5. 双重验证：本地状态机/语音模型先快速响应，云端规则和大模型再复核，提升可靠性。
6. 告警自动化：分析结果可自动发布 alarm 状态，并驱动通知推送和智能家居联动。
7. 多级通知：通过 PushPlus 向家属、社区、医院推送微信、短信、电话等告警提醒。
8. 智能联动：通过 MQTT/Home Assistant 兼容米家等智能家居生态，并用四路继电器控制家庭电器。
9. 用户友好：TFT、Web 面板、HA 面板和语音助手共同提供友好交互，响应迅速、操作直观。
10. 测量全面：覆盖温湿度、气压、气体、人体存在、距离、区域、运动评分和久静时间。

## 第二部分 系统组成及功能说明

### 2.1 整体介绍

系统整体由感知层、边缘控制层、执行交互层、通信层、云端 AI 层、云端展示层、通知处置层和智能家居联动层组成。感知层包括 BME280、MQ 模块、PIR、Rd-03 V2 雷达和可扩展 ESP32-S3 语音识别模块；边缘控制层为 STM32U5，负责融合传感器状态并运行 AppStateMachine；执行交互层包括 TFT、蜂鸣器、SOS/ACK 按钮和四路继电器；通信层由 ESP8266 D1 mini 完成 UART 与 MQTT 转换；云端 AI 层由 analysis_service 的规则引擎和大模型服务组成，负责风险评分、实时摘要、通知建议和告警自动化；云端展示层由 Mosquitto、SQLite、dashboard 和 Home Assistant 组成；通知处置层由 analysis_service 和 PushPlus 组成，面向家属、社区和医院输出分级告警；智能家居联动层通过 Home Assistant/MQTT 对接米家等生态，并结合继电器执行本地电器控制。数据从传感器进入 STM32，经过状态机输出风险等级和事件，分别驱动本地执行端和远程 MQTT 端；云端命令也可通过 MQTT 经 ESP8266 回到 STM32。

### 2.2 硬件系统介绍

#### 2.2.1 硬件整体介绍

硬件以 NUCLEO-U5A5ZJ-Q 为主控板，外接 BME280、MQ 气体模块、PIR、Rd-03 V2 雷达、2.0 英寸 TFT、ESP8266 D1 mini、本地按钮、无源蜂鸣器和四路继电器模块。BME280 通过 I2C1 接入，MQ AO 通过分压后接 ADC1，PIR 与雷达 OT2 作为 GPIO 输入，Rd-03 V2 通过 USART3 和 DMA 接收二进制上报，ESP8266 通过 USART2 与 STM32 通信，TFT 通过 SPI1 显示，蜂鸣器使用 TIM1_CH1 PWM，继电器使用 GPIO 输出控制。继电器可按告警状态自动吸合，也可接受云端/HA 远程命令，用于灯光、排风、提示灯或其他安全隔离后的家庭电器控制。

图片建议：放“硬件连接总览照片 + 标注图”。效果为实物正上方照片，标出每个模块名称和连线接口。制作方法：拍摄俯视图，用 PPT 箭头标注 BME280、MQ、雷达、ESP8266、TFT、按钮、蜂鸣器、继电器。

#### 2.2.2 机械设计介绍

当前作品以原型验证装置为主，机械结构可采用底板固定式布局：将 NUCLEO、传感器、TFT、蜂鸣器、继电器和网关模块固定在亚克力板或 3D 打印底座上，传感器朝向按居家场景布置。Rd-03 V2 雷达应固定在房间入口或活动区侧面，保持探测面朝向人体活动区域；MQ 模块应靠近模拟气体风险区域但远离高温和明火；TFT 与按钮应放在用户容易看到和触达的位置；继电器仅连接低压演示灯，不接市电负载。

#### 2.2.3 电路各模块介绍

BME280 模块接 3.3V、GND、PB8/I2C1_SCL、PB9/I2C1_SDA。MQ 模块由外部 5V 供电，AO 经 2k/3.3k 电阻分压后输入 PC3/ADC1_IN4，并与 STM32 共地。PIR OUT 接 PB0，Rd-03 OT2 接 PC1；Rd-03 RX 接 PB10/USART3_TX，OT1 接 PB11/USART3_RX，供电为 3.3V。ESP8266 使用外部 5V，STM32 PA2/USART2_TX 接其 RX，PA3/USART2_RX 接其 TX。TFT 使用 PA5/SPI1_SCK、PA7/SPI1_MOSI、PD14/CS、PF13/DC、PF12/RST、PD15/BL。按钮 PG8/PG7 上拉输入，闭合接地触发；蜂鸣器 PE9 输出 2 kHz PWM；继电器 IN1-IN4 由 PE13、PF14、PE11、PC0 控制。

图片建议：放“分模块接线表截图”和“关键电路图”。效果为每个模块单独一张小图，标出 VCC/GND/信号线方向。制作方法：用 Fritzing、draw.io 或 KiCad 画简化原理图；MQ 分压电路必须画出电阻比例。

### 2.3 软件系统介绍

#### 2.3.1 软件整体介绍

软件分为 STM32 固件、ESP8266 网关、服务器服务、云端 AI 分析、Web 面板、Home Assistant 配置、PushPlus 通知服务、智能家居联动和 ESP32-S3 语音增强模块。STM32 固件由 Core、Drivers 和 Modules 组成，核心业务模块包括 sensor_mvp、rd03_v2、radar_features、app_state_machine、board_io、comm_wifi、comm_local、status_display 和 app_log。ESP8266 固件解析 STM32 的 S/E/R 帧并发布 MQTT，同时接收 demo/relay topic 并转发为 D/C 帧。服务器端 analysis_service 订阅 status/event，入库并进行规则分析；当状态风险、云端风险或气体数值达到阈值时，llm_service 调用大模型生成更清晰的实时摘要和通知建议。分析结果发布到 `eldercare/node01/analysis`，告警状态发布到 `eldercare/node01/alarm`，并通过 PushPlusNotifier 发送 family、community、hospital 三类通知。dashboard 提供控制台和展示页；Home Assistant 展示环境参数、人体存在、风险等级、AI 摘要和当前告警，并可作为米家等智能家居生态的桥接入口。ESP32-S3 语音助手支持“救命、我摔倒了、我没事、取消报警”等人性化语音指令，将语音风险映射到系统告警流程。

#### 2.3.2 软件各模块介绍

主循环初始化 HAL 外设、通信、显示、状态机、板级 IO 和传感器模块，随后循环执行 SensorMvp_Update、AppStateMachine_Update、BoardIo_Update、云端/语音命令处理、继电器自动化、事件发送、TFT 刷新、状态上报和 LED 心跳。传感器模块每 2 秒读取 BME280，每 500 ms 读取 PIR、Rd-03 OT2、MQ ADC 和雷达状态；MQ 采样采用 32 次去极值平均和 EMA 滤波，ppm 估算基于当前基线。雷达特征模块将 32 个距离门转换为 zone、peak gate、energy sum、motion score、occupied seconds 和 still seconds。状态机模块根据本地 SOS、远程命令、久静、气体阈值和 ACK 超时切换状态，生成事件并写入环形日志。通信模块用 DMA 环形队列发送状态帧和事件帧，解析下行继电器与演示命令。服务器侧收到状态后先执行规则评分，再按阈值调用大模型增强摘要；最终取本地/云端更高风险等级作为告警依据，从而实现本地模型和云端模型的双重验证。

## 第三部分 完成情况及性能参数

### 3.1 整体介绍

## 第四部分 总结

### 4.1 可扩展之处

后续可从四个方向扩展。第一，完善正式看护风险模型，将雷达 still seconds、motion score、zone、MQ 趋势、按钮和语音输入统一为证据链，并让云端大模型结合历史窗口进行趋势摘要，降低误报。第二，补充离线事件缓存和恢复补传的完整实物验证，使断网自治能力更可靠。第三，进一步引入低功耗策略和备用电源，将系统划分为全功能、演示、最小运行三种模式，保留关键检测、二次确认和告警能力。第四，扩展 ESP32-S3 语音识别、Wi-Fi CSI 感知和米家智能家居桥接能力，将其作为隐私友好的增强模态和家庭联动入口，但不替代 STM32 本地状态机。

### 4.2 心得体会

本项目的研发过程说明，嵌入式作品的难点不仅是把单个传感器读出来，而是把采集、判断、显示、执行、联网、日志和验收组织成稳定闭环。早期方案容易被“更多传感器”和“更复杂识别”牵引，但在真实开发中，现场可重复演示、状态可解释、故障可排查比单点功能更重要。因此项目逐步收敛到主动求助、久静无响应和断网自治三条主场景，并围绕这三条场景设计统一状态机。

硬件调试中，Rd-03 V2 雷达的接线和协议解析是典型问题。仅使用 OT2 数字输出只能得到有人/无人，无法发挥雷达距离和距离门能量的价值；改用 UART 后又遇到 NUCLEO 连接器针脚容易误判的问题。通过查阅板卡手册、原理图和实际丝印，最终确认 PB10/PB11 对应的 CN10 外侧列位置，并将接收方式升级为 USART3 RX DMA + Receive-to-Idle，解决了日志和显示刷新时可能丢帧的问题。这体现了硬件资料核对、日志诊断字段和软件接收架构同样重要。

软件设计中，项目尽量避免把业务逻辑堆在 main.c，而是拆分为传感器聚合、雷达特征、状态机、日志、通信、显示和板级 IO 模块。状态机将风险处理变成可追踪的事件：触发、等待确认、用户确认、超时升级、清除告警都对应明确枚举和事件帧。这样在答辩或现场排障时，可以用串口日志、MQTT JSON 和面板时间线解释“系统为什么报警、现在处于什么状态、下一步会做什么”。

通信联调也带来一个认识：STM32 侧不一定要直接构造复杂 JSON。项目采用 STM32 到 ESP8266 的 CSV 帧、ESP8266 到 MQTT 的 JSON 转换，降低了主控侧实现复杂度，同时保留了服务器和前端的可读性。服务器端通过 SQLite 保存状态和事件，用展示面板呈现闭环过程，使作品不只是硬件采集器，而是具备远程可视化和事件复盘能力的系统原型。

当前系统仍有需要完善的地方，例如 MQ ppm 只是基于曲线和环境基线的估算，不能当作标准计量浓度；长时间静止阈值当前为演示值，真实部署需要结合房间位置和老人生活习惯标定；ESP32-S3 语音识别模块和 STM32 主协议还需要进一步统一；米家联动需要结合实际家庭网关或 Home Assistant 插件完成现场配置。后续工作应继续坚持“先闭环、再优化、再扩展”的思路，把每个功能都落实为可验证的现象和可复盘的数据。
