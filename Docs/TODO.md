## 当前开发总原则

从当前版本开始，后续所有功能开发都必须优先服务于以下 3 个主展示场景：

1. 主动求助 / 模拟跌倒后的闭环响应
2. 长时间静止无响应的异常确认与升级
3. 断网或市电异常下的本地自治与日志补传

约束如下：

- 不再以“继续堆更多传感器”作为优先目标
- 不再以房间精细标定、开放式语音对话或复杂 AI 识别作为近期主线
- 不再以“先把人体异常检测做准”作为近期第一优先级
- 状态机、TFT 页面、语音提示、继电器联动、HA 展示、日志设计都必须直接支撑上述 3 个场景
- 新增功能若不能增强这 3 个场景的演示闭环，应降低优先级
- 遥控触发接口必须纳入当前构建目标，用于稳定演示场景一
- 低功耗设计必须纳入后续开发计划，新增功能需评估其对最小运行模式和断电续航的影响
- 当前版本整体按“在线 IoT 闭环项目”推进，优先保证上报、联动、确认、升级、日志和展示稳定

详细需求说明见 `Docs/demo_scenarios_requirements.md`

6.30 前的模块拆解、CRUD、重构范围、人员职责与每日计划见 `Docs/implementation_breakdown_to_0630.md`
